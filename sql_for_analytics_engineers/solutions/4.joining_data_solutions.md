# Lesson 4 Solutions: Joining Data

## Practice Problem 1

### Business Question

Show every visit with the patient's first name.

### What should one row represent?

One visit.

### Starting Table

`visits`

### Join Type

`INNER JOIN`

### Why?

We only want visits with a matching patient record.

### Solution

```sql
SELECT
    v.visit_id,
    v.visit_date,
    p.first_name
FROM visits v
INNER JOIN patients p
    ON v.patient_id = p.patient_id;
```

One visit.

`visits`

### Join Type

`INNER JOIN`

## Practice Problem 3

### Business Question

Show every patient, including those without visits.

### What should one row represent?

One patient per visit when a visit exists. Patients without visits should still appear once.

### Starting Table

`patients`

### Join Type

`LEFT JOIN`

### Why?

The business wants every patient included. An `INNER JOIN` would remove patients who do not have a matching visit.

### Solution

```sql
SELECT
    p.patient_id,
    p.first_name,
    p.last_name,
    v.visit_id,
    v.visit_date
FROM patients p
LEFT JOIN visits v
    ON p.patient_id = v.patient_id;
```

> **Note:** A patient with multiple visits will appear on multiple rows. This is expected because one patient can have many visits.

## Practice Problem 4

### Business Question

Count the number of visits per provider.

### What should one row represent?

One provider.

### Starting Table

`visits`

### Join Type

`INNER JOIN`

### Why?

We only want providers who have visits. Joining to the `providers` table allows us to include the provider's name.

### Solution

```sql
SELECT
    pr.provider_id,
    pr.provider_name,
    COUNT(*) AS visit_count
FROM visits v
INNER JOIN providers pr
    ON v.provider_id = pr.provider_id
GROUP BY
    pr.provider_id,
    pr.provider_name;
```

### Alternative Solution

If the business wanted **every provider**, even providers without visits, start with the `providers` table and use a `LEFT JOIN`.

```sql
SELECT
    pr.provider_id,
    pr.provider_name,
    COUNT(v.visit_id) AS visit_count
FROM providers pr
LEFT JOIN visits v
    ON pr.provider_id = v.provider_id
GROUP BY
    pr.provider_id,
    pr.provider_name;
```

> **Why `COUNT(v.visit_id)` instead of `COUNT(*)`?**  
> `COUNT(*)` would count the provider row even when there isn't a matching visit. Counting `v.visit_id` correctly returns `0` for providers with no visits.

## Practice Problem 5

### Business Question

Count the number of unique patients seen by each provider.

### What should one row represent?

One provider.

### Starting Table

`visits`

### Join Type

`INNER JOIN`

### Why?

The `visits` table connects providers to the patients they have seen.

### Solution

```sql
SELECT
    pr.provider_id,
    pr.provider_name,
    COUNT(DISTINCT v.patient_id) AS unique_patient_count
FROM visits v
INNER JOIN providers pr
    ON v.provider_id = pr.provider_id
GROUP BY
    pr.provider_id,
    pr.provider_name;
```

> **Why `COUNT(DISTINCT)`?**  
> If a patient visited the same provider multiple times, we only want to count that patient once.

## Practice Problem 6

### Business Question

Show every provider and the total revenue generated from their visits.

### What should one row represent?

One provider.

### Starting Table

`providers`

### Join Type

`LEFT JOIN`

### Why?

The business wants every provider included, even providers who haven't generated any revenue yet.

### Solution

```sql
SELECT
    pr.provider_id,
    pr.provider_name,
    COALESCE(SUM(v.revenue), 0) AS total_revenue
FROM providers pr
LEFT JOIN visits v
    ON pr.provider_id = v.provider_id
GROUP BY
    pr.provider_id,
    pr.provider_name;
```

> **Why use `COALESCE`?**  
> Providers without visits will have a `NULL` revenue total. `COALESCE` replaces that `NULL` with `0`.

# Challenge Solution

## Business Question

What was the total claim amount by provider last month?

### What should one row represent?

One provider.

Each row should show a provider and the total claim amount associated with that provider.

### Starting Table

`claims`

### Why?

The business question is asking us to calculate total claim amounts. The `claims` table contains the `amount` we need to sum, so it makes the most sense to start there.

### Which Tables Need to Be Joined?

We need three tables:

- `claims` contains the claim amount.
- `visits` connects each claim to a provider.
- `providers` contains the provider's information.

The relationships look like this:

```text
claims
   ↓ visit_id
visits
   ↓ provider_id
providers
```

A claim belongs to a visit.

A visit belongs to a provider.

### Join Type

Use `INNER JOIN` for both joins.

### Why?

We only want claims that can be connected to a valid visit and provider.

If a claim doesn't have a matching visit, it can't be assigned to a provider.

If a visit doesn't have a matching provider, it also can't be included in the report.

### Solution

For simplicity, we'll assume we want claims from **June 2026**.

```sql
SELECT
    pr.provider_id,
    pr.provider_name,
    SUM(c.amount) AS total_claim_amount
FROM claims c
INNER JOIN visits v
    ON c.visit_id = v.visit_id
INNER JOIN providers pr
    ON v.provider_id = pr.provider_id
WHERE c.claim_date >= '2026-06-01'
  AND c.claim_date < '2026-07-01'
GROUP BY
    pr.provider_id,
    pr.provider_name;
```

### Think Like an Analytics Engineer

Notice the order we solved the problem:

1. Start with the metric.
2. Find the table that contains the metric.
3. Follow the relationships to the dimensions you need.
4. Choose the appropriate join type.
5. Write the SQL.

The SQL is simply the final step in the thought process.

# Validate Your Results

Before trusting your results, ask yourself:

- Does each row represent one provider?
- Did any claims get duplicated after the joins?
- Does the sum of all provider totals equal the total claim amount for June?
- Do the joins follow the business relationships between the tables?

Good Analytics Engineers validate their joins before sharing their results.
