# Lesson 6 Solutions: CTEs & Subqueries

## Practice Problem 1

**Create a CTE named `provider_visits` that returns:**

- provider_id
- total_visits

using the `patient_visits` table.

```sql
WITH provider_visits AS (

    SELECT
        provider_id,
        COUNT(*) AS total_visits

    FROM patient_visits

    GROUP BY provider_id

)

SELECT *
FROM provider_visits;
```

### Explanation

The CTE groups the data by `provider_id` and counts the number of visits for each provider. The final query simply returns the results from the CTE.

## Practice Problem 2

**Using your CTE, return only providers with more than 100 visits.**

```sql
WITH provider_visits AS (

    SELECT
        provider_id,
        COUNT(*) AS total_visits

    FROM patient_visits

    GROUP BY provider_id

)

SELECT *

FROM provider_visits

WHERE total_visits > 100;
```

### Explanation

Notice that the filtering happens **after** the aggregation has already been completed in the CTE. This keeps the query easy to read because the calculation and filtering are separate steps.

## Practice Problem 3

**Create a CTE that calculates total revenue by state. Return only states with more than $50,000 in total revenue.**

```sql
WITH state_revenue AS (

    SELECT
        state,
        SUM(revenue) AS total_revenue

    FROM patient_visits

    GROUP BY state

)

SELECT *

FROM state_revenue

WHERE total_revenue > 50000;
```

### Explanation

The CTE calculates the total revenue for each state. The outer query filters the results to include only high-performing states.

## Practice Problem 4

**Calculate each patient's lifetime revenue, then rank patients from highest to lowest lifetime revenue using `ROW_NUMBER()`. Return the top 10 patients.**

```sql
WITH patient_revenue AS (

    SELECT
        patient_id,
        SUM(revenue) AS lifetime_revenue

    FROM patient_visits

    GROUP BY patient_id

),

patient_rank AS (

    SELECT
        patient_id,
        lifetime_revenue,
        ROW_NUMBER() OVER (
            ORDER BY lifetime_revenue DESC
        ) AS revenue_rank

    FROM patient_revenue

)

SELECT *

FROM patient_rank

WHERE revenue_rank <= 10;
```

### Explanation

This solution intentionally breaks the problem into two logical steps.

The first CTE calculates lifetime revenue for every patient.

The second CTE ranks those patients based on lifetime revenue.

Finally, the outer query returns the top 10.

## Practice Problem 5

**Rewrite this query using a CTE.**

Original Query:

```sql
SELECT *

FROM (

    SELECT
        patient_id,
        COUNT(*) AS visit_count

    FROM patient_visits

    GROUP BY patient_id

) visits

WHERE visit_count > 5;
```

Solution:

```sql
WITH patient_visits_summary AS (

    SELECT
        patient_id,
        COUNT(*) AS visit_count

    FROM patient_visits

    GROUP BY patient_id

)

SELECT *

FROM patient_visits_summary

WHERE visit_count > 5;
```

### Explanation

Both queries return the same results.

The CTE version gives the intermediate result a meaningful name, making it easier to understand and extend later.

# Challenge Solution

**Business Question**

> Show the providers whose average visit revenue is greater than the overall average visit revenue.

### Step 1

Calculate the overall average visit revenue.

### Step 2

Calculate each provider's average visit revenue.

### Step 3

Compare the two averages.

```sql
WITH overall_average AS (

    SELECT
        AVG(revenue) AS overall_avg_revenue

    FROM patient_visits

),

provider_average AS (

    SELECT
        provider_id,
        AVG(revenue) AS provider_avg_revenue

    FROM patient_visits

    GROUP BY provider_id

)

SELECT
    pa.provider_id,
    pa.provider_avg_revenue

FROM provider_average pa

CROSS JOIN overall_average oa

WHERE pa.provider_avg_revenue > oa.overall_avg_revenue;
```

### Why This Works

The `overall_average` CTE returns a single row containing the average revenue across every visit.

The `provider_average` CTE calculates each provider's average visit revenue.

A `CROSS JOIN` makes the single overall average available to every provider so the final query can compare the two values.

This is a common Analytics Engineering pattern: calculate a benchmark once, then compare every group against it.
