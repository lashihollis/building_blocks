# Lesson 5 Solutions: Window Functions

## Question 1

Add each patient's total revenue to every visit.

Expected output:

| patient_id | visit_date | revenue | total_patient_revenue |

```sql
SELECT
    patient_id,
    visit_date,
    revenue,
    SUM(revenue) OVER (
        PARTITION BY patient_id
    ) AS total_patient_revenue
FROM visits;
```

### Why This Works

`PARTITION BY patient_id` creates a separate window for each patient.

`SUM(revenue)` calculates the total revenue within that window while still returning every individual visit.

Unlike `GROUP BY`, no rows are removed.

## Question 2

Number each patient's visits from oldest to newest.

Expected output:

| patient_id | visit_date | visit_number |

```sql
SELECT
    patient_id,
    visit_date,
    ROW_NUMBER() OVER (
        PARTITION BY patient_id
        ORDER BY visit_date
    ) AS visit_number
FROM visits;
```

### Why This Works

`PARTITION BY patient_id` restarts the numbering for each patient.

`ORDER BY visit_date` sorts the visits chronologically before assigning row numbers.

The first visit receives `visit_number = 1`, the second receives `2`, and so on.

## Question 3

For every provider, rank visits from highest revenue to lowest revenue.

Expected output:

| provider_id | visit_date | revenue | revenue_rank |

```sql
SELECT
    provider_id,
    visit_date,
    revenue,
    RANK() OVER (
        PARTITION BY provider_id
        ORDER BY revenue DESC
    ) AS revenue_rank
FROM visits;
```

### Why This Works

`PARTITION BY provider_id` creates a separate ranking for each provider.

`ORDER BY revenue DESC` ranks the highest revenue first.

`RANK()` assigns the same rank to tied values and skips the next rank.

Example:

| revenue | revenue_rank |
|---------|--------------|
| 500 | 1 |
| 400 | 2 |
| 400 | 2 |
| 300 | 4 |

If you want every row to receive a unique number regardless of ties, use `ROW_NUMBER()` instead.

# Challenge Solution

Using the `patient_visits` table, calculate:

- Visit number
- Previous visit date
- Number of days since the previous visit

```sql
WITH patient_visit_history AS (

    SELECT
        patient_id,
        visit_date,
        ROW_NUMBER() OVER (
            PARTITION BY patient_id
            ORDER BY visit_date
        ) AS visit_number,
        LAG(visit_date) OVER (
            PARTITION BY patient_id
            ORDER BY visit_date
        ) AS previous_visit
    FROM patient_visits

)

SELECT
    patient_id,
    visit_date,
    visit_number,
    previous_visit,
    DATE_DIFF(visit_date, previous_visit, DAY) AS days_between_visits
FROM patient_visit_history;
```

### Why This Works

This solution combines two window functions:

- `ROW_NUMBER()` numbers each patient's visits from oldest to newest.
- `LAG()` looks at the previous visit for that same patient.

Once the previous visit date is available, `DATE_DIFF()` calculates the number of days between visits.

By solving one piece of the problem at a time, the final query stays readable and easy to debug.

---

## Key Takeaways

- Window functions **add information** without removing rows.
- `PARTITION BY` defines which rows belong together.
- `ORDER BY` determines the order of calculations within each partition.
- `ROW_NUMBER()` is useful for numbering rows and deduplicating data.
- `RANK()` ranks values while preserving ties.
- `LAG()` compares the current row to a previous row, making it useful for time-based analysis.
