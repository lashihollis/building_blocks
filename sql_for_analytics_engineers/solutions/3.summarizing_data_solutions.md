# Lesson 3 Solutions: Summarizing Data

This file contains the solutions for the practice problems and challenge problem from **Lesson 3: Summarizing Data**.

Remember: an Analytics Engineer doesn't just calculate metrics—they make sure they're calculating the **right** metric.

Before writing an aggregate query, always ask yourself:

- What does one row in the source table represent?
- What should one row in my final result represent?
- Does the business want counts, totals, averages, or something else?

---

# 📝 Practice Problem 1

## Prompt

A clinic manager asks:

> **"How many visits did each provider complete?"**

Return:

- `provider_id`
- Total visits as `total_visits`

Sort the results from the provider with the most visits to the provider with the fewest.

---

## Solution

```sql
SELECT
    provider_id,
    COUNT(*) AS total_visits
FROM visits
GROUP BY provider_id
ORDER BY total_visits DESC;
```

---

## Why This Works

The stakeholder wants to know **how many visits** each provider completed.

Since one row in the `visits` table represents **one visit**, we can count rows.

```sql
COUNT(*)
```

returns the number of visits for each provider.

Because we grouped by `provider_id`, the grain of the result becomes:

> **One row per provider**

Finally, we sort from the highest number of visits to the lowest.

```sql
ORDER BY total_visits DESC;
```

# 📝 Practice Problem 2

## Prompt

A finance manager asks:

> **"What was the total and average visit revenue for each state?"**

Return:

- `state`
- Total revenue as `total_revenue`
- Average visit revenue as `average_visit_revenue`

Sort the results alphabetically by state.

---

## Solution

```sql
SELECT
    state,
    SUM(revenue) AS total_revenue,
    AVG(revenue) AS average_visit_revenue
FROM visits
GROUP BY state
ORDER BY state;
```

---

## Why This Works

The stakeholder wants **two different metrics**.

```sql
SUM(revenue)
```

calculates the total revenue for each state.

```sql
AVG(revenue)
```

calculates the average revenue **per visit** for each state.

Because the query groups by `state`, SQL calculates both metrics independently for each state.

The final grain becomes:

> **One row per state**

Notice that we only grouped by `state`.

Every other selected column is an aggregate function.

# 🏆 Challenge Problem

## Stakeholder Request

> **"I want to understand provider reach. For each provider, show me how many visits they completed and how many unique patients they saw."**

---

## Think Like an Analytics Engineer

Before writing SQL, think through the request.

### Which table should you start with?

The stakeholder is asking about visits.

The `visits` table is the correct starting point because its grain is:

> **One row per visit**

---

### What should one row in the final result represent?

The stakeholder wants metrics **for each provider**.

That means the final result should have:

> **One row per provider**

---

### Why are total visits and unique patients different metrics?

Imagine one patient visits the same provider three times.

| visit_id | provider_id | patient_id |
|----------|-------------|------------|
|1001|10|201|
|1002|10|201|
|1003|10|201|

Using:

```sql
COUNT(*)
```

returns:

```
3 visits
```

Using:

```sql
COUNT(DISTINCT patient_id)
```

returns:

```
1 patient
```

Both metrics are correct.

They answer different business questions.

---

## Solution

```sql
SELECT
    provider_id,
    COUNT(*) AS total_visits,
    COUNT(DISTINCT patient_id) AS unique_patients
FROM visits
GROUP BY provider_id
ORDER BY total_visits DESC;
```

---

## Why This Works

This query calculates two metrics at the same time.

```sql
COUNT(*)
```

counts every visit.

```sql
COUNT(DISTINCT patient_id)
```

counts each patient once for each provider.

Grouping by `provider_id` changes the grain of the result to:

> **One row per provider**

Each provider now has:

- Total visits
- Total unique patients

---

## Analytics Engineer Perspective

This challenge demonstrates an important lesson.

These two metrics sound similar:

- Total visits
- Unique patients

But they answer completely different business questions.

If a provider sees the same patient five times, should that count as:

- Five?
- One?

The answer depends on what the stakeholder is trying to measure.

Analytics Engineers don't start with SQL.

They start by defining the metric.

# Lesson Summary

After completing Lesson 3, you should be able to:

- Count rows using `COUNT(*)`.
- Count unique values using `COUNT(DISTINCT)`.
- Calculate totals using `SUM()`.
- Calculate averages using `AVG()`.
- Find minimum and maximum values.
- Use `GROUP BY` to summarize data.
- Recognize that grouping changes the grain of your results.
- Choose aggregate functions based on the business question—not just the SQL syntax.

The biggest takeaway from this lesson is simple:

> **Before you calculate a metric, make sure you know exactly what you're measuring.**

That's one of the habits that separates an Analytics Engineer from someone who simply knows SQL.
