# Lesson 2 Solutions: Filtering Data

This file contains the solutions for the practice problems and challenge problem from **Lesson 2: Filtering Data**.

Remember: writing valid SQL is only part of the job.

An Analytics Engineer should also understand why each filter is being used and confirm that the filtering logic matches the stakeholder's request.

---

# 📝 Practice Problem 1

## Prompt

A finance manager asks:

> **"Can you show me every claim greater than $2,000?"**

Return:

* `claim_id`
* `patient_id`
* `claim_amount`

Sort the results from the largest claim amount to the smallest.

## Solution

```sql
SELECT
    claim_id,
    patient_id,
    claim_amount
FROM claims
WHERE claim_amount > 2000
ORDER BY claim_amount DESC;
```

## Why This Works

The `WHERE` clause limits the results to claims with an amount greater than $2,000.

```sql
WHERE claim_amount > 2000
```

Because the request says **greater than** $2,000, a claim with an amount of exactly $2,000 would not be included.

The `ORDER BY` clause sorts the largest claims first.

```sql
ORDER BY claim_amount DESC
```

`DESC` means descending order.

The query also returns only the columns requested by the finance manager rather than every column in the `claims` table.

# 📝 Practice Problem 2

## Prompt

A clinic director wants a list of appointments for patients in either Georgia or South Carolina.

Return:

* `appointment_id`
* `patient_id`
* `visit_date`
* `state`

Only include appointments where the state is either `GA` or `SC`.

Sort the results by visit date.

## Solution

```sql
SELECT
    appointment_id,
    patient_id,
    visit_date,
    state
FROM appointments
WHERE state IN ('GA', 'SC')
ORDER BY visit_date;
```

## Why This Works

The stakeholder wants appointments from more than one state.

We could write the filter using `OR`:

```sql
WHERE state = 'GA'
   OR state = 'SC'
```

However, `IN` is cleaner when comparing one column against a list of accepted values.

```sql
WHERE state IN ('GA', 'SC')
```

The `ORDER BY` clause sorts the appointments by visit date in ascending order, meaning the earliest appointments appear first.

```sql
ORDER BY visit_date
```

Because no direction is specified, SQL uses ascending order by default.

## Alternative Solution

The following query is also correct:

```sql
SELECT
    appointment_id,
    patient_id,
    visit_date,
    state
FROM appointments
WHERE state = 'GA'
   OR state = 'SC'
ORDER BY visit_date;
```

Both versions return the same results.

The `IN` version is usually easier to read and maintain, especially if additional states are added later.

# 🏆 Challenge Problem

## Stakeholder Request

> **"I need every cardiology appointment from June 2026 for patients in South Carolina. Please exclude cancelled appointments."**

Before writing SQL, think through the request.

* Which table should you start with?
* Which filters are required?
* Should the filters be combined with `AND` or `OR`?
* Is there anything you should clarify with the stakeholder before running the query?

---

## Think Like an Analytics Engineer

### Which table should you start with?

Start with the `appointments` table because the stakeholder is requesting a list of appointments.

The grain of this table is:

> **One row per appointment.**

### Which filters are required?

The query needs to include only rows where:

* The specialty is Cardiology.
* The patient state is South Carolina.
* The appointment occurred during June 2026.
* The appointment was not cancelled.

### Should the filters use `AND` or `OR`?

Use `AND` because every requirement must be true for an appointment to qualify.

An appointment should not be included unless it meets all four conditions.

### What should you clarify?

Before finalizing the query, an Analytics Engineer may want to confirm:

* Whether `visit_date` is stored as a date or timestamp.
* Whether the specialty value is stored as `'Cardiology'`.
* Whether South Carolina is stored as `'SC'`.
* Whether cancelled appointments are always stored as `'Cancelled'`.
* Whether appointments with a missing status should be included.
* Whether June should be based on the appointment date or another date, such as the date the appointment was created.

These details can change the query and its results.

---

## Solution

```sql
SELECT
    appointment_id,
    patient_id,
    provider_id,
    visit_date,
    specialty,
    state,
    status
FROM appointments
WHERE specialty = 'Cardiology'
  AND state = 'SC'
  AND visit_date BETWEEN '2026-06-01' AND '2026-06-30'
  AND status != 'Cancelled'
ORDER BY visit_date;
```

## Why This Works

Each `WHERE` condition represents one part of the stakeholder's request.

```sql
specialty = 'Cardiology'
```

This limits the results to Cardiology appointments.

```sql
state = 'SC'
```

This limits the results to patients associated with South Carolina.

```sql
visit_date BETWEEN '2026-06-01' AND '2026-06-30'
```

This limits the results to appointments during June 2026.

```sql
status != 'Cancelled'
```

This excludes appointments with a cancelled status.

The conditions use `AND` because every condition must be true.

---

## A More Production-Friendly Date Filter

The original solution works when `visit_date` is stored as a date.

If `visit_date` contains a timestamp, such as:

```text
2026-06-30 14:30:00
```

using an inclusive end date may produce different results depending on the database and data type.

A safer pattern is to include the first day of June and exclude the first day of July.

```sql
SELECT
    appointment_id,
    patient_id,
    provider_id,
    visit_date,
    specialty,
    state,
    status
FROM appointments
WHERE specialty = 'Cardiology'
  AND state = 'SC'
  AND visit_date >= '2026-06-01'
  AND visit_date < '2026-07-01'
  AND status != 'Cancelled'
ORDER BY visit_date;
```

This pattern captures every appointment in June, including appointments that occurred late on June 30.

---

## Important `NULL` Consideration

The following condition excludes cancelled appointments:

```sql
status != 'Cancelled'
```

However, it also excludes rows where `status` is `NULL`.

That happens because SQL cannot determine whether an unknown status is equal to or different from `'Cancelled'`.

If the stakeholder wants appointments with missing statuses included, the filter should be:

```sql
AND (
    status != 'Cancelled'
    OR status IS NULL
)
```

The complete query would be:

```sql
SELECT
    appointment_id,
    patient_id,
    provider_id,
    visit_date,
    specialty,
    state,
    status
FROM appointments
WHERE specialty = 'Cardiology'
  AND state = 'SC'
  AND visit_date >= '2026-06-01'
  AND visit_date < '2026-07-01'
  AND (
      status != 'Cancelled'
      OR status IS NULL
  )
ORDER BY visit_date;
```

Whether missing statuses should be included is a business decision, not just a SQL decision.

That is why clarifying the stakeholder's intent matters.

# Lesson Summary

After completing Lesson 2, you should be able to:

* Compare values using operators such as `=`, `>`, and `!=`.
* Combine required conditions using `AND`.
* combine alternative conditions using `OR`.
* Filter a list of accepted values using `IN`.
* Filter dates and numeric ranges.
* Search for missing values using `IS NULL`.
* Recognize that `NULL` can affect exclusion filters.
* Translate stakeholder requests into intentional filtering logic.

The most important lesson is not simply knowing which operator to use.

It is understanding exactly which rows should be included and which rows should be excluded before writing the query.
