# 📝 Practice Problem 1

### Prompt

Return the following columns from the `providers` table:

- `provider_id`
- `first_name`
- `last_name`
- `specialty`

Sort the results alphabetically by last name.

### Solution

```sql
SELECT
    provider_id,
    first_name,
    last_name,
    specialty
FROM providers
ORDER BY last_name;
```

### Why This Works

This query demonstrates two core concepts from Lesson 1:

- Selecting only the columns you need using `SELECT`.
- Sorting the results using `ORDER BY`.

Notice that we don't use `SELECT *` because the stakeholder only needs specific information.

# 📝 Practice Problem 2

### Prompt

Return a list of patients who live in South Carolina.

Include:

- `patient_id`
- `first_name`
- `last_name`

Sort alphabetically by last name.

### Solution

```sql
SELECT
    patient_id,
    first_name,
    last_name
FROM patients
WHERE state = 'SC'
ORDER BY last_name;
```

### Why This Works

This query combines three skills:

- Selecting specific columns
- Filtering rows with `WHERE`
- Ordering the results

The `WHERE` clause limits the results to patients whose state is `'SC'`.

# 🏆 Challenge Problem

### Stakeholder Request

> "I need a list of every Georgia patient. If we don't know their state yet, I'd rather include them than accidentally leave someone out."

### Before Writing SQL

An Analytics Engineer should think through the request before opening the SQL editor.

**What table should I use?**

The `patients` table because one row represents one patient.

**Could patients appear multiple times?**

No. The grain of the table is one row per patient.

**How should I handle missing states?**

The stakeholder explicitly said they would rather include patients with unknown states than accidentally exclude someone.

That means we should include `NULL` values.

### Solution

```sql
SELECT
    patient_id,
    first_name,
    last_name
FROM patients
WHERE state = 'GA'
   OR state IS NULL
ORDER BY last_name;
```

### Why This Works

This challenge wasn't really about SQL.

It was about understanding the business request.

A technically correct query might only return Georgia patients.

An Analytics Engineer listens to the stakeholder's intent and realizes that patients with missing states should also be included.

That's the difference between writing SQL that works and writing SQL that solves the right problem.
