# Lesson 5: Window Functions

## Overview & Learning Objectives

Window functions let you calculate values across related rows **without reducing the number of rows returned**.

Unlike `GROUP BY`, which combines rows into a summary, window functions keep every row while adding additional context.

By the end of this lesson, you'll be able to:

- Explain when to use a window function instead of `GROUP BY`
- Use `PARTITION BY` and `ORDER BY`
- Apply window functions to common Analytics Engineering problems
- Recognize when a window function is the right tool for the job

---

## Think Like an Analytics Engineer

Analytics Engineers don't use window functions because they're advanced.

They use them because business questions often require **keeping every row while adding context**.

Instead of asking:

> "How do I use `ROW_NUMBER()`?"

Ask yourself:

> **"What information does each row need from the rows around it?"**

When you think about the business question first, the correct window function usually becomes much easier to identify.

---

## Window Functions vs. GROUP BY

A helpful way to think about the difference is this:

Use **`GROUP BY`** when you want **fewer rows**.

Use **window functions** when you want **the same rows with more information**.

### GROUP BY

```sql
SELECT
    patient_id,
    SUM(revenue) AS total_revenue
FROM visits
GROUP BY patient_id;
```

Result:

| patient_id | total_revenue |
|------------|---------------|
| 1 | 250 |
| 2 | 200 |

One row per patient.

### Window Function

```sql
SELECT
    patient_id,
    visit_date,
    revenue,
    SUM(revenue) OVER (
        PARTITION BY patient_id
    ) AS total_patient_revenue
FROM visits;
```

Result:

| patient_id | visit_date | revenue | total_patient_revenue |
|------------|------------|---------|-----------------------|
| 1 | Jan 5 | 100 | 250 |
| 1 | Feb 2 | 150 | 250 |
| 2 | Jan 8 | 200 | 200 |

Every visit is still returned.

The total revenue is simply added to each row.

## Worked Example 1: Total Revenue Per Patient

**Business Question**

How much revenue has each patient generated across all of their visits?

```sql
SELECT
    patient_id,
    visit_date,
    revenue,
    SUM(revenue) OVER (
        PARTITION BY patient_id
    ) AS total_patient_revenue
FROM visits;
```

Now every visit knows the patient's total revenue.

This makes it easy to answer follow-up questions like:

- What percentage of lifetime revenue came from this visit?
- Was this visit above the patient's average?
- Which visit generated the most revenue?

---

## Worked Example 2: Number Each Visit

**Business Question**

Which visit was each patient's first, second, third, and so on?

```sql
SELECT
    patient_id,
    visit_date,
    ROW_NUMBER() OVER (
        PARTITION BY patient_id
        ORDER BY visit_date
    ) AS visit_number
FROM visits;
```

Result:

| patient_id | visit_date | visit_number |
|------------|------------|--------------|
| 1 | Jan 5 | 1 |
| 1 | Feb 2 | 2 |
| 1 | Mar 10 | 3 |
| 2 | Jan 8 | 1 |

Notice we didn't summarize anything.

We simply added another piece of information to every row.

## Worked Example 3: Deduplicating Records

One of the most common Analytics Engineering tasks is keeping only the newest version of each record.

Suppose our `claims` table contains multiple versions of the same claim.

```sql
WITH ranked_claims AS (

    SELECT
        claim_id,
        patient_id,
        updated_at,
        ROW_NUMBER() OVER (
            PARTITION BY claim_id
            ORDER BY updated_at DESC
        ) AS row_num
    FROM claims

)

SELECT
    claim_id,
    patient_id,
    updated_at
FROM ranked_claims
WHERE row_num = 1;
```

We first assign a row number to every version of the claim.

The newest record receives `row_num = 1`.

Then we simply keep those rows.

This approach works across the major SQL dialects.

> **Analytics Engineer Note:** If you're using BigQuery or Snowflake, you can simplify this using `QUALIFY` instead of a CTE. `QUALIFY` isn't supported by every SQL dialect, so we'll stick with the portable approach throughout this course.

---

## Analytics Engineer Tip 💡

When deciding between `GROUP BY` and a window function, ask yourself one question:

> **Do I still need every row?**

- If **no**, use `GROUP BY`.
- If **yes**, use a window function.

That one question will help you choose the right approach far more often than memorizing syntax.
