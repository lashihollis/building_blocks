## 🧠 Think Like an Analytics Engineer

A stakeholder asks:

> **"What's our average patient revenue?"**

Before writing SQL, stop and think.

What exactly are they asking?

Could they mean:

- Average revenue per visit?
- Average total revenue per patient?
- Average revenue for patients seen this month?
- Average revenue for completed visits only?

All of these are valid interpretations.

They also produce different answers.

Before calculating a metric, ask yourself:

- What does one row in my source table represent?
- What should one row in my final result represent?
- Am I summarizing visits or patients?
- Do I need every row or one row per group?
- Should any rows be excluded?

A query can be technically correct and still answer the wrong business question.

Always define the metric before writing the SQL.

# Core Concepts

## Why We Summarize Data

Most tables contain thousands—or even millions—of rows.

Stakeholders don't want to review every record.

They want information they can use to make decisions.

For example, consider this `visits` table.

| visit_id | patient_id | provider_id | state | visit_date | revenue |
|----------|------------|-------------|-------|------------|---------|
|1001|201|10|GA|2026-06-02|150|
|1002|202|11|SC|2026-06-02|225|
|1003|201|10|GA|2026-06-18|175|

One row represents **one visit**.

From this table, we can answer questions like:

- How many visits occurred?
- How much revenue was generated?
- What was the average visit revenue?
- How many unique patients visited?
- How much revenue did each state generate?

These are called **aggregations**.

---

## Aggregate Functions

Aggregate functions summarize multiple rows into a single value.

| Function | Purpose |
|----------|---------|
| `COUNT()` | Count rows or values |
| `SUM()` | Add numeric values |
| `AVG()` | Calculate an average |
| `MIN()` | Return the smallest value |
| `MAX()` | Return the largest value |

---

## COUNT()

Use `COUNT()` when you need to know how many records exist.

### Count Every Row

```sql
SELECT
    COUNT(*) AS total_visits
FROM visits;
```

Because one row represents one visit, this returns the total number of visits.

---

### Count Non-NULL Values

```sql
SELECT
    COUNT(revenue) AS visits_with_revenue
FROM visits;
```

This counts only rows where `revenue` is not `NULL`.

---

### Count Unique Values

```sql
SELECT
    COUNT(DISTINCT patient_id) AS unique_patients
FROM visits;
```

This counts each patient once, even if they had multiple visits.

Think about the business question.

```sql
COUNT(*)
```

answers:

> "How many visits occurred?"

Whereas

```sql
COUNT(DISTINCT patient_id)
```

answers:

> "How many unique patients visited?"

Those are different questions.

---

## SUM()

Use `SUM()` when you want a total.

```sql
SELECT
    SUM(revenue) AS total_revenue
FROM visits;
```

This adds together the revenue from every visit.

---

## AVG()

Use `AVG()` when you need the average value.

```sql
SELECT
    AVG(revenue) AS average_visit_revenue
FROM visits;
```

Because the grain of the table is one row per visit, this calculates the average revenue **per visit**.

It does **not** calculate average revenue per patient.

The grain of your data affects the meaning of every metric.

---

## MIN() and MAX()

Find the smallest and largest values.

```sql
SELECT
    MIN(revenue) AS lowest_revenue,
    MAX(revenue) AS highest_revenue
FROM visits;
```

These functions also work with dates.

```sql
SELECT
    MIN(visit_date) AS first_visit,
    MAX(visit_date) AS most_recent_visit
FROM visits;
```

---

## GROUP BY

Aggregate functions summarize an entire table unless you tell SQL otherwise.

`GROUP BY` allows you to calculate a metric for each category.

### Revenue by State

```sql
SELECT
    state,
    SUM(revenue) AS total_revenue
FROM visits
GROUP BY state;
```

Instead of one total, SQL now returns one total for each state.

| state | total_revenue |
|-------|---------------|
| GA | 325 |
| SC | 225 |

Notice something changed.

The original table had:

> **One row per visit**

The query now returns:

> **One row per state**

Grouping changes the grain of your results.

---

## Grouping by Multiple Columns

You can group by more than one column.

```sql
SELECT
    state,
    provider_id,
    COUNT(*) AS total_visits
FROM visits
GROUP BY
    state,
    provider_id;
```

Now the result contains:

> **One row per provider per state**

Every column added to the `GROUP BY` creates a more detailed result.

---

## Analytics Engineer Perspective

One of the biggest mistakes analysts make is calculating the wrong metric.

Consider these two questions.

> **How many visits did each provider complete?**

```sql
COUNT(*)
```

Now compare it to:

> **How many unique patients did each provider see?**

```sql
COUNT(DISTINCT patient_id)
```

The SQL is almost identical.

The business question is not.

Always define the metric before writing the query.

# Worked Examples

## Example 1 — Count Total Visits

A clinic manager asks:

> **"How many visits are in the visits table?"**

```sql
SELECT
    COUNT(*) AS total_visits
FROM visits;
```

Since one row represents one visit, counting rows answers the question.

---

## Example 2 — Calculate Total Revenue

A finance manager asks:

> **"How much revenue did all visits generate?"**

```sql
SELECT
    SUM(revenue) AS total_revenue
FROM visits;
```

This adds the revenue from every visit.

---

## Example 3 — Revenue by State

A regional director asks:

> **"How much revenue did each state generate?"**

```sql
SELECT
    state,
    SUM(revenue) AS total_revenue
FROM visits
GROUP BY state;
```

The result now contains one row per state.

---

## Example 4 — Count Unique Patients by Provider

A provider operations manager asks:

> **"How many unique patients did each provider see?"**

```sql
SELECT
    provider_id,
    COUNT(DISTINCT patient_id) AS unique_patients
FROM visits
GROUP BY provider_id;
```

A patient who visited multiple times is only counted once for that provider.

---

## Example 5 — Average Visit Revenue

A finance manager asks:

> **"What was the average revenue per visit?"**

```sql
SELECT
    AVG(revenue) AS average_visit_revenue
FROM visits;
```

Notice that this calculates the average **per visit**, not per patient.

# Key Takeaways

- Aggregate functions summarize data into meaningful metrics.
- `COUNT(*)` counts rows.
- `COUNT(DISTINCT column)` counts unique values.
- `SUM()` calculates totals.
- `AVG()` calculates averages at the grain of the source data.
- `GROUP BY` changes the grain of your results.
- Always define the business metric before writing the SQL.
