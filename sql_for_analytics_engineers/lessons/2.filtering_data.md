# Core Concepts

## Why We Filter Data

Stakeholders rarely ask for **all** of the data.

Instead, they ask questions like:

- Show me patients in Georgia.
- Find appointments from last month.
- Which claims were greater than $2,000?
- Who hasn't visited in over a year?

Filtering allows us to narrow a dataset until it answers the business question.

Before choosing a SQL operator, ask yourself:

> **What kind of filter am I trying to apply?**

Most filters fall into one of three categories.

---

## 1. Compare Values

Use comparison operators when you're comparing one value to another.

| Operator | Meaning |
|----------|---------|
| `=` | Equal to |
| `!=` or `<>` | Not equal to |
| `>` | Greater than |
| `>=` | Greater than or equal to |
| `<` | Less than |
| `<=` | Less than or equal to |

### Example

```sql
SELECT
    claim_id,
    claim_amount
FROM claims
WHERE claim_amount > 2000;
```

Here we're asking:

> Return only claims where the amount is greater than $2,000.

Simple comparisons answer a surprising number of business questions.

---

## 2. Combine Conditions

Sometimes one filter isn't enough.

Imagine a stakeholder asks:

> **"Show me cardiology appointments in South Carolina."**

Now two things must be true.

This is where logical operators come in.

### AND

Every condition must be true.

```sql
SELECT *
FROM appointments
WHERE specialty = 'Cardiology'
  AND state = 'SC';
```

### OR

At least one condition must be true.

```sql
SELECT *
FROM patients
WHERE state = 'SC'
   OR state = 'GA';
```

### NOT

Exclude matching rows.

```sql
SELECT *
FROM appointments
WHERE NOT status = 'Cancelled';
```

Whenever you're writing multiple conditions, ask yourself:

> **Should every condition be true, or just one of them?**

That question usually tells you whether to use `AND` or `OR`.

---

## 3. Special Filters

Some business questions come up so often that SQL provides shortcuts.

### IN

Instead of writing multiple `OR` statements...

```sql
WHERE state = 'SC'
   OR state = 'GA'
   OR state = 'NC'
```

...use `IN`.

```sql
WHERE state IN ('SC', 'GA', 'NC');
```

It's shorter, cleaner, and easier to maintain.

---

### BETWEEN

Use `BETWEEN` to filter a range of values.

```sql
SELECT *
FROM appointments
WHERE visit_date
BETWEEN '2026-06-01'
    AND '2026-06-30';
```

This works well for dates, numbers, and other ranges.

---

### LIKE

Use `LIKE` when searching for text patterns.

```sql
SELECT *
FROM patients
WHERE last_name LIKE 'Sm%';
```

Wildcards:

- `%` = any number of characters
- `_` = exactly one character

For example:

| Pattern | Matches |
|----------|---------|
| `'Sm%'` | Smith, Smythe, Small |
| `'%son'` | Johnson, Anderson |
| `'_ohn'` | John |

---

### NULL

Sometimes data is missing.

`NULL` means **unknown**, not blank.

This will **not** work:

```sql
WHERE state = NULL;
```

Instead, use:

```sql
WHERE state IS NULL;
```

Or:

```sql
WHERE state IS NOT NULL;
```

---

### Analytics Engineer Perspective

Notice something about these filters.

An Analytics Engineer doesn't start by thinking:

> "Should I use `IN` or `BETWEEN`?"

Instead, they ask:

> **"What kind of business question am I answering?"**

Then the SQL naturally follows.

- Comparing values? → Use comparison operators.
- Combining requirements? → Use `AND`, `OR`, or `NOT`.
- Looking for a list, range, pattern, or missing values? → Use a special filter.

The SQL is simply the tool.

The business question comes first.

# Worked Examples

## Example 1 — Find Every Cardiology Appointment

```sql
SELECT *
FROM appointments
WHERE specialty = 'Cardiology';
```

We're returning only appointments for the Cardiology specialty because that's what the stakeholder asked for.

---

## Example 2 — Find Large Claims

```sql
SELECT
    claim_id,
    patient_id,
    claim_amount
FROM claims
WHERE claim_amount > 1000;
```

Notice that we're only selecting the columns needed to answer the question.

---

## Example 3 — Find Cardiology Appointments in South Carolina

```sql
SELECT *
FROM appointments
WHERE specialty = 'Cardiology'
  AND state = 'SC';
```

Both conditions must be true for a row to be returned.

---

## Example 4 — Find Patients in Multiple States

```sql
SELECT
    patient_id,
    first_name,
    last_name,
    state
FROM patients
WHERE state IN ('SC', 'GA')
ORDER BY last_name;
```

Using `IN` is easier to read and maintain than multiple `OR` statements.

# Key Takeaways

- Filtering helps answer the business question by returning only the relevant rows.
- Most filters fall into one of three categories:
  - Compare values
  - Combine conditions
  - Apply special filters
- Always think about the business logic before choosing SQL syntax.
- Great Analytics Engineers filter with intention—not by trial and error.
