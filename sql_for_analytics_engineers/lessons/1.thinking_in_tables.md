## 🧠 Think Like an Analytics Engineer

Let's go back to our manager's question.

> **"How many patients do we have in Georgia?"**

Before writing SQL, ask yourself:

- Which table should I start with?
- Why is that the correct table?
- What does one row in that table represent?
- Could the same patient appear multiple times?
- Is there anything I should clarify before answering?

An experienced Analytics Engineer doesn't immediately write code.

They first understand **the business question** and **the shape of the data**.

Once those two things are clear, the SQL becomes much easier.

# Core Concepts

## What is SQL?

SQL stands for **Structured Query Language**.

It's the language we use to ask questions of data stored in relational databases.

Think of SQL like Google—but instead of searching the internet, you're searching your company's data.

The better your question, the better your answer.

---

## Understanding Relational Databases

Businesses don't keep all of their information in one giant spreadsheet.

Instead, data is organized into multiple related tables.

At Healthy Horizons, we'll work with four primary tables throughout this course.

| Table | One Row Represents |
|--------|--------------------|
| Patients | One patient |
| Providers | One provider |
| Appointments | One appointment |
| Claims | One insurance claim |

Notice something.

Each table has a different purpose.

That leads us to one of the most important concepts in SQL.

---

## Table Grain

**Table grain describes what one row represents.**

If you understand the grain of a table, you'll avoid many of the mistakes beginners make.

Consider the Patients table.

| patient_id | first_name | state |
|------------|------------|-------|
|101|Sarah|GA|
|102|James|SC|

Each row represents one patient.

Now look at Appointments.

| appointment_id | patient_id | provider_id | visit_date |
|---------------|------------|-------------|------------|
|5001|101|22|2026-07-01|
|5002|101|22|2026-08-10|

Sarah appears twice.

Is that bad data?

No.

One row now represents **an appointment**, not a patient.

The grain changed.

Always ask yourself:

> **"What does one row represent?"**

If you remember one thing from today's lesson, remember that question.

# Worked Examples

## Example 1 — Return Every Patient

```sql
SELECT *
FROM patients;
```

This returns every column for every patient.

When you're exploring a table for the first time, using `SELECT *` is perfectly reasonable because you're trying to understand what data is available.

---

## Example 2 — Return Only the Columns You Need

```sql
SELECT
    patient_id,
    first_name,
    last_name
FROM patients;
```

Most business questions don't require every column.

Selecting only what you need makes your queries easier to read and your results easier to understand.

---

## Example 3 — Filter Your Results

```sql
SELECT
    patient_id,
    first_name,
    last_name
FROM patients
WHERE state = 'GA';
```

The `WHERE` clause filters your results before they're returned.

In this case, we're only interested in patients who live in Georgia.

---

## Example 4 — Sort the Results

```sql
SELECT
    patient_id,
    first_name,
    last_name
FROM patients
WHERE state = 'GA'
ORDER BY last_name;
```

The stakeholder didn't ask for the data to be sorted...

…but sorted results are easier to read.

Little touches like this improve the experience for whoever receives your analysis.
